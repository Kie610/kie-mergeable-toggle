# kieMergeableToggle

VRChat アバター用の NDMF プラグイン。

> **alpha** — PC 実機まで実測で確認しています。Quest (モバイル GPU) は未検証です。

## 何をするもの

手書きアニメーターレイヤーで `GameObject` のオンオフをしているメッシュトグルを、
ビルド時に**別の隠しかたへ機械的に変換**します。

AAO (Avatar Optimizer) の自動メッシュ統合は「アクティブ状態のアニメーション」で
メッシュをグルーピングするため、トグルが違うメッシュ同士は統合されません。
本ツールで変換するとメッシュ側は常時アクティブになり、表示切替は別の機構が担うので、
**トグル挙動を保ったまま AAO がメッシュを統合できる**ようになります。

ポリゴン数は削減ツールで、マテリアル数は統合ツールで、いずれも非破壊で減らせます。
表示切替条件が一致しない SkinnedMeshRenderer だけは他のどのツールでも統合できません。
そこがこのツールの担当範囲です。

## 使い方

1. アバタールートに `Kie/kieMergeableToggle` コンポーネントを追加
2. 検出されたトグル一覧から変換したいものを選ぶ (クリーンな候補は初期状態でオン)
3. そのままビルドするだけ

レイヤー構造・パラメータ・メニューは一切変更しません。非破壊 (ビルド時のみ)。

## 隠しかた — infinimation

全頂点のデルタを `+Infinity` にしたブレンドシェイプを生成し、`0⇔100` で切り替えます。
頂点が非有限座標へ飛ぶのでプリミティブがクリップ段で破棄され、**完全に消えます**。

| ボーン | コンストレイント | マテリアル | ポリゴン | 消えかた | シェーダ依存 |
|---|---|---|---|---|---|
| ±0 | ±0 | 統合される | ±0 | 完全に消える | 無し |

- パフォーマンスランクの計上項目はひとつも増えない (増えるのは VRAM のみ、下記)
- 初期非表示はブレンドシェイプのウェイトとしてそのままシリアライズされるので、
  ワールド入室直後の一瞬だけ見える、といったことが起きません
- 代償は VRAM (1 トグルあたり頂点数×デルタ分)。こちらはランクの計上対象外です

実測 (AAO 併用・PC):

| アバター | SMR | マテリアルスロット | ボーン |
|---|---|---|---|
| Shinano | 11 → **2** | 14 → **6** | 272 → **272** |
| MUMUS_all | 21 → **4** | 36 → **18** | 453 → **453** |

> 0.5.0-alpha より前は、シェイプ(関節)・シェイプ(軸)・UVタイル破棄・NaNimation の
> 4 機構から選ぶ形でした。infinimation がすべての面で上回ったため 1 本化しています。
> Quest での挙動だけは未検証です。

## 非表示中は専用 PhysBone も止める (0.6.0-alpha)

衣装の揺れボーン (PhysBone) はアーマチュア側に付いているため、衣装を隠しても
揺れ続けて CPU を使います。これは元のトグル (`m_IsActive` を 0 にする) でも同じです。

`disablePhysBonesWhenHidden` (既定オン) は、**その衣装のためだけに存在する** PhysBone を
見つけて、隠すのと同じタイミングで `m_Enabled` を落とします。判定は保守側です:

- PhysBone のチェーンを使うレンダラー (ウェイトを持つメッシュ + ボーンにぶら下がる
  オブジェクト) が、**全部そのトグルで隠れる**場合だけ止めます
- 素体と共有しているボーン (胸・尻尾・複数衣装で共用のスカートなど) は対象外
- 編集時に無効な PhysBone、`m_Enabled` が既にアニメーションされている PhysBone にも
  触れない設計です

実測 (保守判定で止められた本数): Shinano 10/61 本、MUMUS_all 68/89 本。

再表示した衣装の揺れはレスト位置から始まります (Unity の仕様で、無効化中の
揺れ状態は保持されないため)。削れるのは PhysBone のシミュレーションに掛かる
実行時 CPU で、パフォーマンスランクは動きません (ランクは無効なコンポーネントも
数える仕様)。

## 注意点

- **インスペクタの一覧は参考表示です。ビルド結果とは一致しません。** 正はビルドログです。
  - **ビルド時にトグルを生成するツールのぶんは一覧に出ません**が、変換はされます。
    編集時にはまだクリップが存在しないためです。実測では Avatar Menu Creator
    (Narazaka) が該当し、衣装アバターで一覧 8 件に対しビルド 18 件になりました。
    MA Object Toggle も同様です。**`m_IsActive` を生成しうる NDMF ツールは無数に
    あるため、一覧を完全にすることは原理的にできません。**
  - **逆に、一覧に出ても変換されないものがあります。** ビルド中に階層を張り替える
    パッケージ (AvatarPoseSystem など) では、編集時とビルド時でパスが別物になるためです。
- 「要注意」と表示される候補は、非表示中も止められないコンポーネントがトグル配下に
  あります。挙動を確認のうえ手動でオンにしてください。
- 「適用不可」と表示される候補は、隠蔽シェイプを追加できないメッシュを含みます
  (頂点を持つ SkinnedMeshRenderer が対象です)。放置するとビルド時に変換対象から外れます。
- 「非表示中は専用 PhysBone も止める」で止まるのは、**その衣装だけが使っている**
  PhysBone に限ります。素体と共有しているボーン (胸・尻尾・共用スカートなど) は
  誤停止を避けるため止めません。何を止めたかはビルドログに出ます。

## 依存

- VRChat SDK - Avatars 3.7 以上
- NDMF (`nadena.dev.ndmf`) 1.14 以上

効果を出すには **Avatar Optimizer** が必要です (依存には入れていません。本ツールは
「AAO が統合できる状態にする」だけで、統合するのは AAO です)。
シェーダには依存しません。

**Modular Avatar** は必須ではありませんが、入っている場合は MA Merge Animator が
持ち込むトグルも扱います。本ツールは MA より後に走るので、ビルド時にトグルを生成する
ツール (MA Object Toggle、Avatar Menu Creator など) のぶんも変換対象になります。
